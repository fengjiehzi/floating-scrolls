# 万卷浮生 · 书库页电影化执行提示词

请在现有「万卷浮生」React 前端中重构书库页。目标不是制作营销落地页，也不是另起一套设计系统，而是把当前 `/library` 改造成玩家可以长期使用的典籍入口。

页面核心感受：

> 这里不是文件列表，而是玩家曾经进入、并且随时可以重返的故事。

## 一、项目事实与边界

必须以仓库现状为准：

- React 19 + TypeScript + Vite 6。
- Tailwind CSS 4 已通过 `@tailwindcss/vite` 接入。
- Zustand 管理前端状态。
- React Router 提供 `/library` 与 `/story` 路由。
- Lucide React 是唯一图标库。
- GSAP 已存在，但书库页只需要现有 CSS 动效；不要增加动画依赖。
- `frontend/design.md` 是锁定设计系统，`frontend/tokens.css` 是色彩、字体、间距、圆角与动效令牌的唯一来源。
- 桌面端保留现有左侧导航，移动端保留底部坞站。
- 当前 React 书库使用 Zustand 和本地演示数据，不接入需要认证的后端接口。

本次不要：

- 安装 Framer Motion。
- 引入 Supabase、RLS 或新数据库表。
- 降级 React、Tailwind 或 Vite 版本。
- 引入 Inter、Playfair Display 或新的 Google Fonts。
- 重写导航、路由、Modal、PageState 或全局设计系统。
- 修改角色、法宝、战斗、剧情或设置页面。
- 实现真实文件上传、认证或云端持久化。

## 二、视觉方向

页面属于锁定的 Atmospheric game UI 与 Edge Workbench 结构：

- 墨夜背景使用 `--color-paper` 和 `--color-paper-2`。
- 绢纸文字使用 `--color-ink` 和 `--color-ink-2`。
- 鎏金主强调使用 `--color-accent`。
- 青玉只表达正在阅读等积极状态。
- 朱砂只用于必要的危险或印记，不把整个页面做成红金宫廷风。
- 标题使用现有 `--font-display-family`，正文使用 `--font-body-family`，标题保持 upright。
- 容器使用细线、小圆角、切角感和留白，不堆叠毛玻璃卡片。
- 强调色在单个视口内保持克制，不使用渐变文字。

书库页的视觉记忆点应来自：

1. 一张大幅、非对称的续读案卷。
2. 一列紧凑的最近翻阅记录。
3. 使用真实名著人物素材的藏书卡片。
4. 极细的章节进度线和清晰的状态标签。

不要添加：

- 漂浮粒子、纸屑、印章碎片或环境装饰。
- 磁吸元素、鼠标追随、像素墨块或 12×8 tile reveal。
- 自动滚动跑马灯、伪分类品牌条或装饰轮播。
- 通用卡片缩放、彩色光晕和厚阴影。
- 全屏居中的 Hero 或作品集式大标题。

## 三、页面信息架构

### 1. 页头

- 保留现有应用页头结构。
- 小标签：`典籍总目`。
- 主标题：`书库`。
- 描述：`这里收录你曾进入的故事。人物、章节与选择，会在一次次翻阅中沉淀成可重返的世界。`
- 主操作：`典籍入卷`，继续打开现有 Modal。

### 2. 上层：续读工作台

桌面使用非对称两栏：

- 左侧约占三分之二，显示当前正在阅读的典籍。
- 右侧约占三分之一，显示最近翻阅记录。
- 平板和手机改为上下排列。

续读案卷必须显示：

- 封面人物图。
- `正在阅读 / 未开始 / 已完成` 状态。
- 书名、作者、来源。
- 简介。
- 已提取角色数、字数和最后翻阅时间。
- 当前章节、总章节和派生出的百分比。
- `继续阅读`；没有进行中进度时显示 `进入典籍`。

选择逻辑：

1. 优先选择 `readingStatus === 'reading'` 且最近翻阅时间最新的书。
2. 没有正在阅读的书时，选择最近更新的书作为推荐入卷。

最近翻阅列表：

- 排除主续读书。
- 仅展示拥有 `lastReadAt` 的记录。
- 按时间倒序，最多三项。
- 每项展示状态、书名、作者和相对时间。
- 点击后进入现有 `/story`。

### 3. 下层：全部藏卷

标题为 `全部藏卷`，包含搜索、筛选、数量和内容网格。

筛选项固定为：

- 全部
- 正在阅读
- 已收藏
- 已完成
- 本地入卷

搜索范围：

- 书名
- 作者
- `charactersExtracted` 中的角色名

筛选与搜索同时生效。没有结果时使用现有 `PageState`，文案为：

- 标题：`没有找到对应典籍`
- 说明：`调整搜索词或筛选条件后再试。`

### 4. 藏书卡片

桌面三列、平板两列、手机单列。每张卡片显示：

- 16:10 封面。
- 来源：`名著典藏 / 本地入卷`。
- 状态：`未开始 / 正在阅读 / 已完成`。
- 书名、作者。
- 已提取角色数和字数。
- 有章节数据时显示当前章节与 2px 进度线。

交互要求：

- 打开典籍与收藏必须是两个并列、独立的按钮，禁止嵌套 `<button>`。
- 整张主内容按钮进入 `/story`。
- 收藏按钮使用 `aria-pressed`，收藏变化只保存在当前页面会话。
- 封面缺失时使用排版式卷宗占位，不使用通用插画。
- hover 只改变边线、墨色或位移 1–2px，不缩放图片和卡片。

## 四、数据模型

在现有 `Book` 上增加：

```ts
type BookSourceType = 'classic' | 'upload'
type BookReadingStatus = 'not_started' | 'reading' | 'completed'

interface Book {
  // 保留原字段
  sourceType: BookSourceType
  readingStatus: BookReadingStatus
  currentChapter: number
  totalChapters: number
  lastReadAt: string | null
  isFavorite: boolean
}
```

阅读百分比只在渲染时计算：

```ts
totalChapters <= 0
  ? 0
  : clamp(Math.round(currentChapter / totalChapters * 100), 0, 100)
```

不要保存重复的 `readingProgress` 字段。

新增到当前会话的典籍默认值：

```ts
sourceType: 'upload'
readingStatus: 'not_started'
currentChapter: 0
totalChapters: 0
lastReadAt: null
isFavorite: false
```

## 六、动效与无障碍

- 页面首次进入只做一次 420ms 的透明度和 10px 位移编排。
- hover 和 active 只使用 `transform`、颜色与边线。
- `prefers-reduced-motion` 或 `data-motion="off"` 时改为不超过 120ms 的透明度变化。
- 所有按钮和输入最小点击区域 44×44px。
- 使用现有全局 `:focus-visible` 双层焦点逻辑，不让焦点环参与动画。
- 数字区域使用 `tabular-nums`。
- 进度条包含 `role="progressbar"`、`aria-valuemin/max/now` 和明确标签。
- 320px 宽度下不出现横向页面滚动；筛选项本身可以在局部横向滚动。

## 七、响应式规则

### 1180px 以上

- 续读区为主案卷 + 最近翻阅侧栏。
- 藏书网格三列。

### 768–1180px

- 续读主案卷独占一行。
- 最近翻阅变为横向三栏记录。
- 藏书网格两列。

### 767px 以下

- 页头操作换行。
- 主案卷封面与内容上下排列。
- 最近翻阅恢复单列。
- 筛选项在局部横向滚动。
- 搜索框全宽。
- 藏书网格单列。
- 底部导航不得遮挡最后一张卡片。

## 九、验收

完成后必须：

1. 运行 `npm run lint`。
2. 运行 `npm run build`。
3. 在 1440、768、414、375、320px 检查布局。
4. 验证五种筛选、按角色搜索、收藏切换、无结果状态、入卷 Modal、新增典籍和 `/story` 跳转。
5. 检查 `aria-pressed`、进度语义、键盘焦点和 reduced-motion。
6. 不把现有 `/api/characters` 后端不可用错误算作本次回归，但不得引入新的控制台错误。
