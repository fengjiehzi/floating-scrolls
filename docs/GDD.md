# 《万卷浮生》Godot 离线版 GDD

## 1. 产品定位

《万卷浮生》是面向 Windows 10/11 与 Android 的 2D 插画式横屏离线游戏。玩家从藏经阁进入中国古典文学书卷，在原著事件锚点中做选择、获得能力并完成主动回合制战斗。

首期目标是交付一个可独立完成的《西游记》约 30 分钟纵切，用它验证“读剧情—做选择—改变构筑—进行战斗—收藏结局”的完整循环。

## 2. 固定边界

首期只包含八卷：

1. 《西游记》
2. 《三国演义》
3. 《封神演义》
4. 《红楼梦》
5. 《水浒传》
6. 《白蛇传》
7. 《史记》
8. 《聊斋志异》

《西游记》为可玩卷，其余七卷只展示封面、简介、人物与法宝图鉴，并明确标记“待开放”。首期不包含其他作品、跨卷自由对战、多人联机、账号、云存档、排行榜、上传解析、动态生成、3D、竖屏、iOS、macOS、Linux 或手柄操作。

## 3. 平台与交互

- 引擎：Godot 4.7.2，GDScript。
- 渲染：Compatibility renderer。
- 设计基准：`1280×720`，`canvas_items + expand`。
- 输入：点击/触摸、确认、返回；主要触控目标不小于 `48×48`。
- Android：横屏、沉浸模式、边缘到边缘显示，并按显示安全区调整根容器。
- 桌面：窗口与全屏切换。

### 藏经阁场景

藏经阁采用 2.5D 分层插画表现：远处山阁、近处廊柱与灯笼、透视地砖，以及前后两排带书脊和纸页厚度的古籍。沿用已有书卷插画，由 Godot 2D 节点绘制空间层次。

- `scenes/library/library_hall.tscn`：独立藏经阁场景；`Composition/Books` 下的八个 `Marker2D` 控制书卷的位置与远近缩放。
- `scenes/library/book_stand.tscn`：可复用书卷展台，封面跟随稳定书卷 ID 加载。
- 点击或触摸书卷更新左侧卷宗说明，再通过主按钮进入原有卷宗页面；未开放书卷仍只提供资料。
- 桌面指针带动轻微分层视差，选卷有抬升与聚光反馈；“减少动态效果”关闭视差与过渡动画，触控不依赖悬停。
- 收藏结局、继续剧情、图鉴和设置沿用原有流程；选卷不修改存档。

## 4. 核心循环

```text
藏经阁选卷
  → 查看卷册资料
  → 进入剧情节点
  → 在原著锚点内选择
  → 获得属性、技能、形态或法宝
  → 完成 1v1 战斗
  → 到达路线结局
  → 解锁图鉴与结局记录
```

剧情选择不能改写关键原著事实，只能改变孙悟空的属性增量、技能组合、战斗准备和最后的态度结算。

## 5. 《西游记》纵切

### 第一章：花果山

- 石猴出世
- 水帘洞称王
- 混世魔王战

### 第二章：方寸山与龙宫

- 菩提授艺：七十二变或筋斗云
- 龙宫取宝：解锁如意金箍棒与法宝行动

### 第三章：大闹天宫

- 官封弼马与齐天旗
- 天兵统领战
- 齐天大圣形态
- 二郎神战
- 五行山下
- “心猿待悟”或“齐天不屈”

两个结局都保持孙悟空被压五行山的原著事实。

## 6. 战斗规则

- 玩家固定控制孙悟空，每场为 1v1。
- 行动包含普通攻击、防御、最多 3 个已解锁技能和一次法宝行动。
- 技能消耗 MP；使用后进入 3 回合冷却。
- 防御沿用统一防御曲线，并降低下一次受到的伤害。
- 法宝每场只能使用一次，在生命未满时恢复生命。
- 敌人使用完全本地的规则选择行动。
- 最多 12 回合；超时按双方剩余生命比例判定。
- 战败只能重试本战或返回藏经阁，不进入路线结局，也不保存失败消耗和惩罚。
- 不存在跨作品倍率、次元压制或强制秒杀。

## 7. 内容数据

运行时不读取旧前端文件、数据库或网络。内容由以下 Godot `Resource` 表达：

- `BookDefinition`：ID、标题、作者、封面、主题、开放状态、剧情图。
- `CharacterDefinition`：所属书卷、立绘、属性、技能、形态、资料完整度。
- `ItemDefinition`：所属书卷、美术、装备效果、原著说明。
- `StoryGraph`：起点与 `story`、`battle`、`reward`、`ending` 节点。
- `BattleDefinition`：参战角色、敌人、回合限制、奖励和胜利节点。

所有引用使用稳定英文 ID。内容注册时阻止重复 ID、悬空节点、缺失图片和跨书卷引用。现有资料共迁移 22 个人物和 23 件法宝；只有简介而缺少完整战斗数据的人物作为未解锁图鉴项存在。

## 8. 存档

- 单档路径：`user://save_v1.json`。
- 设置路径：`user://settings.cfg`。
- 固定版本：`schema_version: 1`。
- 保存内容：当前节点、选择历史、属性增量、技能/法宝/形态、已完成战斗、图鉴、结局和书卷进度。
- 自动保存：选择确认、战斗胜利、结局到达、Android 进入后台和应用关闭。
- 文件不存在时创建新档；损坏时保留一份带时间戳的损坏文件并创建新档，同时给出提示。
- 重开当前书卷清除本轮路线和属性，保留图鉴与已见结局。
- 清除全部进度需要二次确认。

## 9. 全局服务

Autoload 仅有：

- `ContentRegistry`：构造、查询和校验内置内容。
- `GameState`：推进剧情、提交战斗胜利和维护运行状态。
- `SaveService`：存档、设置、损坏降级和后台补存。

界面通过信号读取和提交状态，不直接持有数据库或远端会话。

## 10. 验收

- Headless 测试必须验证 8 卷、12 节点、3 场战斗、2 个结局和全部资源引用。
- 固定随机种子验证伤害、MP、冷却、防御、法宝和 12 回合结算。
- 验证存档往返、重启续玩、损坏降级、卷内重开和清除全部进度。
- 在 `1280×720`、`1920×1080`、`2400×1080` 验证布局与触控。
- Windows 包与 Android Debug APK 必须能够从藏经阁完成任一结局。
- Android 包不得申请 `INTERNET` 权限。
- 正常设备目标 60 FPS，不得出现缺图、悬空节点、无法返回或进度阻断。
